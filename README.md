# h264-editing-utils  
**Коллекция утилит для работы с H.264.**  

[![CI](https://github.com/ferrovovan/h264-editing-utils/actions/workflows/ci.yml/badge.svg)](https://github.com/ferrovovan/h264-editing-utils/actions/workflows/ci.yml)

Проект нацелен на создание инструментов для точной и эффективной работы с видеопотоками H.264.

## Основные цели проекта
1. **Упрощённая обработка H.264:**  
   + Вырезание фрагментов с минимальным перекодированием (тело — байт-в-байт,
     перекодируется только нарушающий границы «хвост» GOP).  
   + Точность до кадра и до миллисекунды (`--exact`), а не до GOP.  
   + Честный display-порядок, открытые GOP, интерлейс (PAFF/MBAFF).  

2. **Удобство для разработчиков и пользователей:**  
   + Исходный код имеет чёткую структуру, где всё упорядочено.  
   + Стандарты хранения файлов в папках:  
     - Исходный код располагается исключительно в папке `source`.  
     - Все данные и утилиты разделены по функциональным папкам.
3. **Приверженность свободному ПО:**  
   + Проект полностью соответствует принципам GNU и распространяется под свободными лицензиями.  

## Используемая библиотека
За основу взята свободная библиотека [h264bitstream](https://github.com/aizvorski/h264bitstream).  
Потому что:  
   а. Она свободная (*GNU Lesser General Public License*);  
   б. Написана на Си;  

Библиотека подключена как git submodule в `source/vendor/h264bitstream` и собирается как статическая библиотека, с которой линкуются утилиты. Из неё используются `h264_stream.c`/`h264_sei.c`/`h264_nal.c`; SPS/PPS/slice header доработаны в `source/common`.

## Сборка
Зависимости: CMake >= 3.16 и компилятор C11; `ffmpeg`/`ffprobe` нужны только для интеграционных тестов.

Необязательные (для `--smart` у `h264-cut`): `libx264-dev libavcodec-dev libavutil-dev`
(иначе `h264-cut` собирается без `--smart`, а тесты `--smart` пропускаются). `mp4-cut`
дополнительных зависимостей не требует — ISO-BMFF читается и пишется своим кодом.

```bash
git clone --recursive <адрес репозитория>   # submodule h264bitstream обязателен
cmake -B build
cmake --build build
ctest --test-dir build                      # unit + интеграция (tests/run.sh) + fuzz
```

Если репозиторий уже клонирован без submodule: `git submodule update --init --recursive`.  
Бинарники утилит складываются в `build/source/<имя-утилиты>/`.

## Релиз

Релиз — аннотированный тег `v*` на `main`; CI (`release` job) собирает
статические бинари, CHANGELOG из `HISTORY.md` и GitHub Release. Первый
стабильный релиз — **v1.0** (2026-10-28): копирующий и точный режимы
`h264-cut`, `--smart`, `mp4-cut`, avcc-конвертеры; 11 unit-тестов,
160 интеграционных проверок против ffprobe, чистые санитайзеры.
(Черновые локальные теги `v0.2`/`v1.0.0`/`v1.1` не публиковались и отброшены
— без хвостов, единственный номер v1.0.)

## Утилиты
- [`h264-cut`](./source/h264-cut/README.md) — вырезание диапазона кадров из «сырого» H.264 битстрима (raw Annex B): побайтовая копия тела, `--smart` (минимальное перекодирование стартового хвоста GOP через libavcodec→x264), `--exact` с точностью до кадра/мс, `--json`, поддержка открытых GOP и интерлейса.
- [`mp4-cut`](./source/mp4-cut/README.md) — побайтовое вырезание диапазона из видео-дорожки single-track MP4 (ISO-BMFF): свои читалка и писатель боксов, таймстемпы и B-порядок сохраняются, перекодирования нет.
- [`avcc2annexb`](./source/avcc2annexb/README.md) / [`annexb2avcc`](./source/annexb2avcc/README.md) — конвертеры length-prefixed (AVCC) ↔ Annex B и разбор/сборка `avcC` (14496-15).
