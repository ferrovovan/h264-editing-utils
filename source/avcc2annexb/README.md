# avcc2annexb

`avcc2annexb` конвертирует H.264 ES с length-prefixed NAL (big-endian,
«AVCC»-транспорт MP4/MDAT) обратно в raw Annex B: перед каждым NAL
пишется канонический старт-код `00 00 00 01`, payload переносится
байт-в-байт.

```
avcc2annexb [-n N] [-c AVCFILE] INPUT.avcc OUTPUT.264
```

| Опция | Аргумент | Описание |
|---|---|---|
| `-n` | `N` | Размер поля длины NAL во входе, байт (`2`..`4`), по умолчанию `4` |
| `-c` | `AVCFILE` | Файл с `AVCDecoderConfigurationRecord` (`avcC` из MP4): SPS/PPS из него записываются в начало выхода перед ES |
| `-h`, `--help` | — | Справка в stdout, выход `0` |

## Поведение

* С `-c` в начало результата кладутся SPS, затем PPS из конфига
  (4-байтные старт-коды) — так поток из MDAT, у которого параметр-сеты
  живут только в `avcC`, становится самодостаточным Annex B.
* Конвейер симметричен `annexb2avcc`: round-trip
  `annexb2avcc | avcc2annexb` даёт ту же последовательность NAL, что и
  исходник (сравнение — по payload'ам NAL, старт-коды нормализованы).

## Коды выхода

| Код | Значение |
|---|---|
| `0` | Успех |
| `1` | Ошибка использования |
| `2` | Не удалось прочитать вход, разобрать avcC или преобразовать поток |
| `4` | Ошибка записи выходного файла |

Все сообщения об ошибках — в stderr с префиксом `avcc2annexb: `.

## Пример

```sh
avcc2annexb in.avcc out.264                       # голый ES
avcc2annexb -c avcC.bin -n 4 in.avcc out.264      # параметр-сеты из avcC
```
