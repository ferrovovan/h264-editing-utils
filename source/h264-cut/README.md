# h264-cut

`h264-cut` вырезает диапазон кадров из «сырого» H.264 битстрима (raw Annex B
byte stream) **без перекодирования**: кадры копируются как есть, поэтому
качество не теряется, а скорость работы ограничена только вводом-выводом.

Утилита строит индекс потока (раскладка NAL-юнитов по кадрам, порядок
декодирования и отображения, recovery point SEI и clock timestamp из SEI
picture timing), по нему определяет границы вырезки, выравнивает левую
границу на ближайший пригодный якорь (IDR или recovery point) и записывает
получившийся диапазон NAL-юнитов в выходной файл. При необходимости в
начало результата дописываются актуальные SPS/PPS.

Полезная нагрузка NAL-юнитов записывается **байт-в-байт** из исходника
(без перекодирования и правок). Нормализуется только транспортная
обёртка: перед каждым NAL пишется канонический 4-байтный старт-код
`00 00 00 01`, а хвостовые нули (`trailing_zero_8bits`) между NAL из
исходника отбрасываются.

## Синтаксис

```
h264-cut [опции] INPUT.264
```

## Опции

| Опция | Длинная форма | Аргумент | Описание |
|---|---|---|---|
| `-l` | `--list` | — | Список кадров в stdout и выход `0`. Не совместима с `-f`/`-t`/`-e`/`-o` |
| `-f` | `--from-frame` | `N` | Первый сохраняемый кадр (0-based, порядок **декодирования**, включительно) |
| `-t` | `--to-frame` | `M` | Последний сохраняемый кадр (0-based, порядок декодирования, включительно; по умолчанию — последний кадр) |
| `-e` | `--exact` | `T0-T1` | Диапазон по времени **отображения**, формат `HH:MM:SS.mmm-HH:MM:SS.mmm` (миллисекунды необязательны) |
| — | `--fps` | `FPS` | Явный fps (десятичное число); при его отсутствии таймбаза берётся из VUI/SEI, см. «Таймбаза `t` и `--exact`» |
| `-o` | `--output` | `FILE` | Файл результата (обязателен для вырезания) |
| `-h` | `--help` | — | Справка в stdout, выход `0` |

Длинные опции принимаются как в форме `--opt val`, так и в форме `--opt=val`.

### Формат вывода `--list`

```
# dec_id disp_id type idr frame_num poc   t        nal_range   byte_range
0        0        I    1   0         0     0.000    0-3         0-4095
1        2        P    0   1         2     0.080    4-5         4096-9000
...
```

Здесь `dec_id` — индекс в порядке декодирования, `disp_id` — позиция в
порядке отображения (`-`, если порядок отображения неизвестен),
`t` — время отображения в секундах (`-`, если таймбаза недоступна; см.
«Таймбаза `t` и `--exact`»), `nal_range`/`byte_range` — диапазон NAL-юнитов
и байт в файле (включительно; `byte_range` — от начала первого NAL до конца
последнего). Параметрические NAL (SPS/PPS/SEI/AUD), стоящие перед кадром,
относятся к этому следующему кадру и входят в его `nal_range`.

В колонке `type` к типу кадра (`I`/`P`/`B`/`S`/`X`) добавляются суффиксы
открытых GOP:

* `L` — leading picture: не-референсный кадр после якоря с `poc` меньше
  `poc` якоря (например `BL`, `PL`). При вырезке, начинающейся с якоря,
  такой кадр переносится с битыми зависимостями.
* `R` — AU кадра несет SEI recovery point (например `IR`).

### Таймбаза `t` и `--exact`

Приоритет источников времени (для колонки `t` — пункты 2–4, для `--exact`
— все):

1. явный `--fps`;
2. VUI `fixed_frame_rate_flag` + `timing_info` (`t = disp_id / fps`);
3. clock timestamp из SEI picture timing (`cnt_type 0`, `n_90kHz 0`,
   суточные переполнения размотаны) — для VFR-потоков; в stderr
   выводится предупреждение `внимание: display-время взято из SEI picture
   timing (VFR)`;
4. VUI `timing_info` без флага `fixed_frame_rate_flag` (так пишет x264) —
   как в пункте 2.

## Коды выхода

| Код | Значение |
|---|---|
| `0` | Успех |
| `1` | Ошибка использования (неверные опции, отсутствие `-o`, несовместимые опции) |
| `2` | Ошибка чтения/парсинга входного потока либо недоступные метаданные (нет VUI-тайминга и не задан `--fps`, неизвестен порядок отображения) |
| `3` | Запрошенный диапазон невозможен (нет IDR слева от границы, пустой диапазон, `from > to`, `from` за концом потока) |
| `4` | Ошибка ввода-вывода при записи выходного файла |

Все сообщения об ошибках выводятся в stderr с префиксом `h264-cut: `.

## Примеры

Показать список кадров:

```sh
h264-cut --list in.264
```

Вырезать кадры с 30-го по 90-й включительно (нумерация в порядке
декодирования):

```sh
h264-cut -f 30 -t 90 -o cut.264 in.264
```

Вырезать фрагмент с 3.5-й по 7-ю секунду времени отображения:

```sh
h264-cut --exact 00:00:03.500-00:00:07.000 -o cut.264 in.264
```

## Ограничения

* Поддерживается только raw Annex B (`*.264`/`*.h264`); контейнеры (MP4,
  MKV, TS) и встроенные таймкоды не читаются.
* Номера кадров в `-f`/`-t` задаются в **порядке декодирования**, а не в
  порядке отображения (используйте `--list`, чтобы их сопоставить).
* Левая граница всегда сдвигается назад к ближайшему пригодному якорю —
  IDR или recovery point (`recovery_frame_cnt == 0 && exact_match &&
  !broken_link`; об открытой GOP сигналируют суффиксы `R`/`L` в `--list` и
  сообщение в stderr): вырезка всегда начинается с самодостаточной точки,
  иначе результат недесибелен.
* Leading-кадры открытых GOP (`L`), попавшие в диапазон, в копирующем
  режиме переносятся с битыми зависимостями — утилита предупреждает об
  этом в stderr; корректная их обработка — перекодирование (`--smart`,
  этап R).
* Правая граница не расширяется: хвостовые B-кадры, которые по времени
  отображения опережают последний сохранённый кадр, остаются за отрезком.
* `--exact` требует таймбазы: `--fps`, VUI-тайминг или SEI picture timing
  (см. выше); без них — ошибка с кодом `2`.
* Чересстрочный контент (поля) поддерживается не полностью.
* При `pic_order_cnt_type == 1` порядок отображения не вычисляется,
  поэтому `--exact` для таких потоков недоступен.
