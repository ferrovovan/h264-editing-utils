# mp4-cut

`mp4-cut` вырезает диапазон сэмплов из видео-дорожки файла MP4 (ISO-BMFF,
ISO/IEC 14496-12) **без перекодирования**: полезные нагрузки сэмплов
копируются байт-в-байт, поэтому качество не теряется, а скорость ограничена
только вводом-выводом. В отличие от `h264-cut` (raw Annex B) здесь разбором и
сборкой контейнера занимается свой код (`source/common/iso.{h,c}`) — сторонние
библиотеки не используются.

Утилита читает `moov` (`trak`/`mdia`/`minf`/`stbl`), раскрывает таблицы сэмплов
(`stts`/`ctts`/`stss`/`stsc`/`stsz`/`stco`/`co64`) в плоский список
`{смещение, размер, dts, pts, sync}`, по нему определяет границы вырезки,
выравнивает левую границу назад на ближайший sync-сэмпл (IDR) и пишет новый
самодостаточный MP4: `ftyp` и описание сэмпла `avc1/avc3` переносятся как есть,
таблицы `stbl` пересобираются под разрез.

Полезная нагрузка каждого сэмпла (вместе с 4-байтными length-prefix'ами NAL)
копируется **байт-в-байт**. Composition-смещения (`pts - dts`, бокс `ctts`)
сохраняются, поэтому B-порядок отображения не ломается. Длительности
дорожки/фильма пересчитываются под разрез; список правки (`elst`), если он был,
**отбрасывается** (задокументированная нормализация — время начинается с
первого оставленного сэмпла).

## Синтаксис

```
mp4-cut [опции] INPUT.mp4
```

## Опции

| Опция | Длинная форма | Аргумент | Описание |
|---|---|---|---|
| `-l` | `--list` | — | Список сэмплов видео-дорожки в stdout и выход `0` |
| `-f` | `--from-frame` | `N` | Первый сохраняемый сэмпл (0-based, порядок декодирования; граница сдвигается назад на sync) |
| `-t` | `--to-frame` | `M` | Последний сохраняемый сэмпл (по умолчанию последний) |
| `-e` | `--exact` | `T0-T1` | Диапазон по времени отображения, `HH:MM:SS.mmm-HH:MM:SS.mmm` |
| `-o` | `--output` | `FILE` | Файл результата (обязателен для вырезания) |
| `-h` | `--help` | — | Справка |

Колонки `--list`: `dec_id` (порядок декодирования), `pts_t`/`dts_t` (секунды),
`key` (`K` — sync-сэмпл), `size` (размер сэмпла в байках).

## Коды выхода

`0` — успех; `1` — ошибка использования; `2` — контейнер/поток не поддерживается
(например аудио-дорожка, фрагментированный или зашифрованный MP4); `3` —
некорректный диапазон; `4` — ошибка ввода-вывода.

## Ограничения v1

- Ровно одна видео-дорожка `avc1`/`avc3`; аудио/субтитры и несколько
  видео-дорожек — отказ с понятным сообщением (для аудио: `ffmpeg -an`).
- Только нефрагментированные, незашифрованные файлы (`moof`/`mvex`/`sinf`/`pssh`
  — отказ).
- Файл результата больше 4 ГБ не пишется (`co64` в писателе не реализован).
- Перекодирования нет: левый край, попавший в середину GOP, сдвигается назад на
  sync-сэмпл (как побайтовый режим `h264-cut`).

## Пример

```bash
mp4-cut -l input.mp4                 # осмотреться
mp4-cut -f 40 -o out.mp4 input.mp4   # с 40-го сэмпла до конца (левый край — на IDR)
mp4-cut -e 0:00:01.600-0:00:03.200 -o out.mp4 input.mp4
```
