# annexb2avcc

`annexb2avcc` конвертирует «сырой» H.264 битстрим (raw Annex B byte stream)
в формат с length-prefixed NAL (big-endian) — тот же транспорт, что лежит
в MDAT-боксах MP4/MOV («AVCC»-формат).

```
annexb2avcc [-n N] INPUT.264 OUTPUT.avcc
```

| Опция | Аргумент | Описание |
|---|---|---|
| `-n` | `N` | Размер поля длины NAL в выходе, байт (`2`..`4`), по умолчанию `4` |
| `-h`, `--help` | — | Справка в stdout, выход `0` |

## Поведение

* Перед каждым NAL пишется `N`-байтное big-endian поле длины, затем сам
  NAL **байт-в-байт** (эмуляционные `00 00 03`-байты сохраняются как есть).
* Старт-коды любой длины и хвостовые `trailing_zero_8bits` исходника —
  только транспорт и отбрасываются (равила те же, что у `h264-cut`).
* **Все NAL переносятся в выход, включая SPS/PPS.** В MP4 параметр-сеты
  живут в боксе `avcC`, здесь контейнера нет — это raw-конвейер, и
  параметр-сеты остаются в теле потока.

## Коды выхода

| Код | Значение |
|---|---|
| `0` | Успех |
| `1` | Ошибка использования |
| `2` | Не удалось прочитать/преобразовать входной поток |
| `4` | Ошибка записи выходного файла |

Все сообщения об ошибках — в stderr с префиксом `annexb2avcc: `.

## Пример

```sh
annexb2avcc in.264 out.avcc            # 4-байтные длины (как по умолчанию в mp4)
annexb2avcc -n 2 in.264 out.avcc       # 2-байтные длины
```

Обратная конвертация — `avcc2annexb`.
