# SOUL.md — смысл проекта

## Зачем этот проект существует

Точка входа в монтаж H.264 сегодня — это выбор между двумя плохими вариантами:
резать только по ключевым кадрам (неточность в секунды) или перекодировать всё
(потеря качества всего материала, часы machine-time, раздувание файла).
Проект даёт третий путь: **правку потока без ущерба для его основной части**.

## Ядро: «минимальное перекодирование»

Это определяющая идея, всё остальное — средства:

> **Тело вырезки переносится байт-в-байт. Перекодируется только то, что иначе
> невалидно.**

- Кадры, чьи зависимости целиком лежат внутри вырезки, переносятся как есть —
  побитово идентично источнику. Ни одного лишнего квантователя не проходит
  через материал, который можно перенести.
- «Хвосты» — кадры у границ вырезки, привязанные к частям, в вырезку не
  вошедшим (стартовый неполный GOP, открытые GOP и их leading/trailing кадры,
  B-кадры, ссылающиеся за правый край), — допиливаются: декодируются с полным
  контекстом источника и перекодируются так, чтобы их зависимости замкнулись
  внутри результата.
- Перекодирование — всегда вынужденная мера и всегда локально. Если задача
  решается копированием — копирование побеждает.

Из этого следуют продуктовые решения: вырезка с точностью до кадра и до
миллисекунды, а не до GOP; честный display-порядок; работа с реальными
«грязными» потоками (открытые GOP, VFR, усечённые файлы), а не только с
учебными.

## Принципы

1. **Язык — C (C11).** Потоковый парсер, у которого нет рантайма-наследника.
2. **Свободное ПО.** Код — GPLv3+, документация — GFDL 1.3. Зависимости только
   совместимых лицензий (h264bitstream — LGPL, x264 — LGPL, libavcodec — LGPL).
3. **Сначала поток, потом контейнер.** Raw Annex B — родная стихия; MP4/MKV —
   надстройка над тем же ядром, а не наоборот.
4. **Стандарт — источник истины, практика — источник проверки.** Конспекты
   по H.264 ведутся в `docs/` по ходу дела; эталонным оракулом в тестах служит
   ffprobe, а перекодированные кадры проверяются эталонным полным
   перекодированием.
5. **Каждый байт на выходе объясним.** Копия — так побайтно, нормализации
   (например start code до 4 байт) — только документированные.

## Чем проект не является

- Не альтернатива ffmpeg как универсальному конвертеру.
- Не GUI-редактор. Мы — скальпель, а не комбайн.
- Не библиотека для произвольного H.264: растём из задач утилит, обобщаем
  потом.
